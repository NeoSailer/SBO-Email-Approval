# 승인 이력 동기화 (v1.5.5)

현재 서버가 지원하는 구매 오더(22), 판매 견적(23), 구매 견적(540000006)을 대상으로 한다.

## 실행 시점

- 서버 시작 및 5분 주기: OWDD/WDD1의 대기·진행·승인·거절 등 모든 상태를 동기화한 뒤 승인 완료 초안을 변환한다.
- 이메일 승인·거절 성공 직후: 해당 WddCode를 동기화한다. 실패 시 SAP 처리 성공 사실과 재시도를 사용자에게 알린다.
- 공식문서 변환 직전: 같은 초안의 승인 요청 전체를 보존하고 커밋한 뒤 Service Layer를 호출한다. 보존 실패 시 변환을 호출하지 않는다.
- 공식문서 변환 직후: 실제 문서 키·번호·상태를 갱신한다. 동기화만 실패하면 성공한 변환을 실패로 보고하지 않고 로그를 남겨 주기 작업에서 복구한다.

## 저장 규칙

- `@PVI_APVH`: 변경 이력 추가. 기존 행은 수정/삭제하지 않는다.
- `@PVI_ARVC`: WddCode별 최신 스냅샷 갱신.
- 두 테이블을 하나의 Serializable 트랜잭션으로 커밋한 후에만 변환 API를 호출한다. 조회, 필드, 권한 또는 저장 오류가 발생하면 변환도 중단한다.
- 같은 내용의 재시도는 기존 해시를 재사용한다. 변환 실패 후에도 저장된 이력은 유지한다.
- `Tissin_Addon_Logistics/src/Snapshot.cs`와 같은 28개 UDF, XML 및 SHA-1 내용/이벤트 키 형식을 사용한다. 승인자, 단계 이름/키/순서, 답변 날짜/시간/비고와 초안/템플릿 정보가 보존된다.

테이블 및 28개 UDF는 기존에 준비되어 있어야 한다. EmailApproval의 HANA 계정에는 원본 테이블 조회 및 두 사용자 테이블 INSERT/UPDATE 권한이 필요하다. 자동 스키마 생성은 하지 않는다.

공식문서는 OWDD의 확정 문서 키, 보존된 공식문서 키, 해당 유형의 `draftKey` 순으로 확인한다. 여러 문서가 매칭되면 임의로 연결하지 않고 실패한다. OPOR/OQUT/OPQT 조회 권한도 필요하다.

OWDD가 삭제되어도 보존된 ARVC 행을 조회하여 공식문서와 연결한다. XML과 마지막 승인 상태는 보존하고 `U_Source=N`으로 표시한다. 공식문서 상태는 `U_DocState`에 반영하며, 삭제된 승인 상태를 추측하지 않는다. 헤더가 남고 WDD1 단계만 사라진 경우에도 이전 XML의 단계 내역을 유지한다.

5분 사이의 모든 중간 변경을 추적하는 이벤트 수집기는 아니다. 외부 SAP 클라이언트가 첫 조회 전에 원본을 삭제하면 관찰하지 못한 이력은 복구할 수 없다.

검증: 계약 테스트에서 XML 내 승인 단계/비고 보존, 키 구분, 28개 필드 구성, 재시도 내용 해시 안정성, 내용 변경 감지를 확인한다. 실제 연동 결과는 [2026-09-19 검증 기록](INTEGRATION_20260919.md)을 참고한다.

## 배포 ZIP 생성

프로젝트 루트에서 실행한다.

```powershell
.\Build-Release.ps1
```

프로젝트 버전을 읽고 복원 → Release 계약 테스트 → publish → 버전 확인 → ZIP 및 SHA256 파일 생성 순으로 실행한다. 실패 시 ZIP을 만들지 않는다. 출력은 `publish/EmailApprovalServer-날짜-v버전-시분초.zip`이다. 기존 산출물은 덮어쓰지 않는다.

현재 `EmailApprovalServer/Config/appsettings.xml`을 포함한다. 테스트 회사로 설정을 바꾸거나 서버에 자동 배포·재시작하지 않는다. 실제 SAP 연동 검증은 자동 실행하지 않는다.
