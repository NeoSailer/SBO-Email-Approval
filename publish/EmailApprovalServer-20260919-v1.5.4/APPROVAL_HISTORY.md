# 공식문서 변환 전 승인 이력 보존

`ApprovalService.SaveDraftToDocumentAsync`는 `DraftsService_SaveDraftToDocument` 호출 전에 HANA에서 해당 초안의 모든 OWDD 요청 및 WDD1 단계를 읽어 보존한다. 이메일 승인 후 변환과 자동 변환 모두 적용된다.

- `@PVI_APVH`: 변경 이력 추가. 기존 행은 수정/삭제하지 않는다.
- `@PVI_ARVC`: WddCode별 최신 스냅샷 갱신.
- 두 테이블을 하나의 Serializable 트랜잭션으로 커밋한 후에만 변환 API를 호출한다. 조회, 필드, 권한 또는 저장 오류가 발생하면 변환도 중단한다.
- 같은 내용의 재시도는 기존 해시를 재사용한다. 변환 실패 후에도 저장된 이력은 유지한다.
- `Tissin_Addon_Logistics/src/Snapshot.cs`와 같은 28개 UDF, XML 및 SHA-1 내용/이벤트 키 형식을 사용한다. 승인자, 단계 이름/키/순서, 답변 날짜/시간/비고와 초안/템플릿 정보가 보존된다.

테이블 및 28개 UDF는 기존에 준비되어 있어야 한다. EmailApproval의 HANA 계정에는 원본 테이블 조회 및 두 사용자 테이블 INSERT/UPDATE 권한이 필요하다. 자동 스키마 생성은 하지 않는다.

저장 내용은 **변환 직전 상태**다. 변환 후 공식문서 키/상태 갱신은 이 변경에 포함되지 않는다. 이미 사라진 과거 원본은 복구할 수 없다. 다른 SAP 클라이언트에서 직접 실행하는 변환은 이 서버의 보존 경로를 통과하지 않는다.

검증: 계약 테스트에서 XML 내 승인 단계/비고 보존, 키 구분, 28개 필드 구성, 재시도 내용 해시 안정성, 내용 변경 감지를 확인한다. 실제 연동 결과는 [2026-09-19 검증 기록](INTEGRATION_20260919.md)을 참고한다.
