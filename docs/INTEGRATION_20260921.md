# v1.5.5 검증 기록 — 2026-09-21

- SBOTSS에서 35개 승인 요청을 전체/상태별 개별 동기화했다.
- 현재 테이블과 이력 테이블의 28개 값 일치, 35건의 저장 금액과 실제 DocTotal 일치, 반복 동기화 시 이력 중복 없음 확인.
- 공식문서가 연결된 7건의 문서 번호·상태를 실제 전표와 대조했다.
- 원본 삭제 및 WDD1만 삭제된 경우의 XML 보존은 계약 테스트로 검증했다. 이 검증을 위해 SAP 원본을 삭제하지 않았다.
- Service Layer 로그인 문제는 해결되지 않았으므로 실제 승인/거절 → 변환 API를 포함한 종단간 검증은 미완료다.

## 문서 총액 0원 원인과 수정

SBOTSS_NEW에서 SELECT로 조회한 37건의 저장 금액은 0이었으나 원본 초안/공식문서 총액은 정상 값이었다. 운영 데이터는 변경하지 않았다.

HANA reader의 GetValue가 반환하는 HanaDecimal을 reader를 닫은 후에 변환하는 경로가 원인이었다. 조회 중 CLR decimal로 복사하도록 수정하고 금액 매개변수의 Decimal/정밀도/소수 자릿수를 명시했다. 실제 UDF 값도 비교하여 해시만 맞고 값이 잘못 저장된 경우를 다시 동기화한다. 기존 APVH 이력은 수정하지 않고 올바른 값으로 새 이력을 추가한다.

기존 검증은 현재/이력 테이블 비교에 동일한 숫자 읽기 경로를 사용하여 이 문제를 발견하지 못했다. 검증 프로그램도 숫자를 복사하도록 수정하고 원본 DocTotal과의 대조를 추가한 뒤 35건 전체가 통과했다.

애드온 조회는 원본 공식문서 → 원본 초안 → 보존 금액 순으로 표시한다. 회사 통화 표시는 유지한다. 선택 기준과 결과 창은 메뉴에서 열 때 SAP 작업 영역 중앙에 배치하도록 소스를 수정했다.

수정한 ReportQuery.cs에서 SQL을 추출하여 SBOTSS_NEW에서 읽기 전용으로 실행했다. 조회된 37건 모두 정상적인 0이 아닌 원본 총액을 반환했다. 애드온 조회 전용 소스 검사도 통과했다. 애드온 실행 파일 빌드, 배포 및 실제 SAP 화면 위치 검증은 수행하지 않았다.
